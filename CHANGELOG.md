# Changelog

All user-facing changes are recorded here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions follow semantic versioning while the public interface is in beta.

## Unreleased

### Added

- `airlock handoff recommended` applies a suggested order that follows capability rather than price, so a frontier route falls to another frontier route on a different provider and the metered route finally has somewhere to go. Routes you have not connected are dropped, so the shape follows your own providers, and a source left with no reachable peer keeps its default rather than being written as never hands off.
- `airlock handoff` shows and edits the handoff tree. Choosing your own order previously meant hand-writing `failover.json` with exact model IDs, suffixes and all, which is easy to get wrong and gives no feedback until the next launch fails. The command prints the current order for every route, marks which entries are yours and which are derived, and takes short route names: `airlock handoff set sol opus grok`. `off` opts a route out entirely, `clear` restores its default, and `reset` clears every choice. A name that does not exist is refused with the list of names that would have worked, and the file is validated before it is written so a bad edit cannot break the next session.
- Retrying a rate limit inside the proxy is now capped when Airlock is the caller. Airlock chooses the replacement model itself, so the proxy's three retries with backoff were a delay paid for nothing: measured at 175 seconds before a handoff that then took 9. The carried proxy build reads `CCP_MAX_RATE_LIMIT_RETRIES`, and Airlock sets it to 0 when it starts the service. Set `AIRLOCK_PROXY_RATE_LIMIT_RETRIES` to keep some retries. Only rate limits are capped; a dropped connection keeps the full budget, because there is no alternative to switch to.

- Effort controls now work for every root, including an OpenRouter root. Profiles that seat non-Claude models declare the effort capability tokens for every family slot they fill and set `CLAUDE_CODE_ALWAYS_ENABLE_EFFORT=1`, so `/effort` moves the selected route. Anthropic-rooted sessions keep Claude Code's normal behavior.
- The auto mode permission classifier now uses the smallest model seat a non-Anthropic session serves instead of spending the premium root on routine permission checks. Hybrid sessions prefer Claude Haiku, pure OpenAI and Grok profiles use their economical seat, and a single-model OpenRouter profile uses its root because no smaller seat exists. Set `AIRLOCK_AUTO_MODE_MODEL` to an exact model ID to override the choice, or to `off` or `none` to clear the override. Anthropic-rooted sessions leave the Claude Code default untouched.
- A declared OpenRouter route can now lead the mixed-provider profile as its exact root. `airlock hybrid ROUTE` starts that route while the Claude Code family slots stay wrapper-backed, and `airlock hybrid choose` lists declared routes. Windows seeds the same managed effort used by the other roots, so these sessions start there too. Other declared OpenRouter routes remain subject to `AIRLOCK_EXTRA_USAGE_POLICY`.
- A reserved `auto` hybrid root resolves at each launch to Fable when it is included, then Opus, then Sonnet. It never selects a model that requires confirmed extra usage. Fresh setup saves `AIRLOCK_HYBRID_MODEL=auto`; an existing configuration without a saved root keeps Sonnet until the maintainer chooses otherwise.
- Sessions using Airlock's router can fail over after an upstream HTTP 402, 429, or 529 to another enabled model in the same usage category, for up to three hops. Models enter a bounded cooldown, later requests skip every cooling route without contacting it, and a fully exhausted chain returns an honest 429 without reflecting the upstream body. The default `ask` policy uses included models only, `never` creates no chains, and `allow` may use extra-usage peers. Session snapshots and diagnostics record the frozen chains, cooldowns, skips, exhaustion, and original model.
- `airlock status` now shows the active router profile, pinned root, and a bounded timestamped list of recent actions, including failover, cooldown skips, OpenRouter effort clamps, and safe error replacement. The managed SessionEnd hook displays a shorter notice. Both paths use only loopback diagnostics, stay friendly or silent when the router is unavailable, and never render prompts, headers, credentials, provider error bodies, or arbitrary fields from unknown events.
- A user-owned `models.json` declares extra provider models without an Airlock release. Each entry names an exact model id, its provider, effort ceiling, optional context window, cost category, and enabled flag. Launchers resolve declared ids for their provider, managed sessions render each enabled entry as an `airlock-custom-*` Agent that joins failover chains in its declared cost category, and a malformed file fails the launch with the offending entry named. Stock configurations behave exactly as before.
- Effort forwarding now honors each OpenRouter route's real ceiling instead of one blanket portable maximum. A request above the route ceiling is lowered just enough, the clamp diagnostic records the requested value, forwarded value, and ceiling, and registry metadata or a `models.json` declaration can raise a route's ceiling when its endpoint documents stronger support.
- Rate-limit failover chains gain a deliberate last resort: the session's declared OpenRouter root, such as Ox Alpha, is appended after the same-category peers of every other chain, while OpenRouter requests never receive it. Set `AIRLOCK_OPENROUTER_CHAIN_PEER=off` before launching to restore the previous chains.
- The doctor script reports Grok models that the installed `claude-code-proxy` catalog advertises but the saved configuration does not enable, so a newly launched model surfaces as a declaration instead of staying invisible. The check is informational and enables nothing on its own.
- Handoff now survives a context window that is too small. A peer that rejects a request because the conversation does not fit is recognized as an overflow rather than a broken request, the chain keeps walking, and peers with a known too-small window are skipped without a round trip. When no peer fits, the router condenses older history into one structured brief through the destination provider's economy worker, which must already be enabled in the session, keeping the system prompt and the most recent turns word for word and preserving tool call and result pairing. Briefs for the shared part of a conversation are cached, so later turns only pay to condense what is new. If no compaction model is available or the call fails, older turns are trimmed to fit instead, and a conversation that fits nowhere ends with a clear message rather than a raw provider error. `airlock mode overflow auto|truncate|summarize|off` selects the behavior, `auto` is the default, and `airlock mode failover never` disables it along with the rest of handoff. Diagnostics and the end of session summary report each step.
- A rate limit that belongs to the whole subscription now cools the whole provider instead of one model at a time. Anthropic, OpenAI, and Grok meter a plan rather than a single model, so a chain used to spend a round trip discovering that each remaining sibling was limited too. Once a second distinct model of the same provider is limited inside the same window, later requests skip that provider's routes without contacting them until the cooldown ends. One limited model still cools only itself, because a single reading is not enough evidence, and OpenRouter is never escalated because it meters credits per request. The escalation is recorded in diagnostics.

- A user-owned `failover.json` (path overridable with `AIRLOCK_FAILOVER_FILE`) declares an exact rate-limit handoff order per model, replacing the derived same-category chain for each source it names. Peers are tried top to bottom and may mix providers and cost categories, since writing the file is itself the upspend decision; an empty peer list opts that source out of handoff entirely. Extra-usage peers still require the `allow` policy, `never` disables declared chains along with derived ones, unknown model names fail the launch with the offending entry named, and a source you do not name keeps its normal chain.

- A handoff now announces itself. Claude Code sends one request and receives one answer, so a reply produced by a replacement model was indistinguishable from a reply by the model that was asked for. A managed `Stop` hook now prints a short notice at the end of any turn where the router switched models, naming both: which model was unavailable and which one actually answered. It reports only what was recorded since the previous turn, never repeats a notice, and stays silent when the router is unreachable.
- The replacement model is now told that it is the replacement. Its system prompt still described the model that was asked for, so it answered in that model's name and gave the wrong answer when asked which model it was. This was observed live: a worker handed from `gpt-5.6-sol` to `grok-4.6` reported itself as `gpt-5.6-sol`. The retargeted request now carries a short routing note stating which model was unavailable and which model is serving the turn. The note is appended so any cached prefix stays intact, and both IDs come from the validated route table rather than from request content.

### Changed

- Switching handoff off now leaves an Anthropic rate limit exactly as the provider sent it. `airlock mode failover never` removed the chains but still replaced the response with Airlock's own message, so turning the feature off did not restore the behavior you get without Airlock. With no chain to walk there is nothing to gain by rewriting the answer, so it is passed through. Other providers keep the safe local message even then, because their error bodies are foreign text arriving at a client that expects Anthropic's shape; those replies now carry the upstream `Retry-After`, so the client still backs off on real timing.

- An Anthropic rate limit now reaches Claude Code untouched instead of being handed to another provider. Claude Code already recognizes its own provider's limits, reports when the allowance resets, and can continue afterwards, but only when it sees the real response. Airlock sat in front of every Claude request, caught the 429, and either switched to another provider or replaced the reply with its own, so that handling could never run and a subscription you were waiting on was quietly swapped for one you were not. The response is now forwarded with its status, headers, and body intact and no chain is walked. Set `AIRLOCK_ANTHROPIC_RATE_LIMIT=handoff` before launching to restore the previous behavior. The change is limited to 429 from Anthropic: 529 means an overloaded server, 402 means a spent balance, neither is a wait, and no other provider has client-side handling to defer to.

### Fixed

- A handoff now tries the peers of the model that was asked for, top to bottom, which is what a declared order has always promised. The walk continued from the chain of whichever hop had just failed, so only the first peer of a declared order was honoured and the second came from a list nobody named. Seen live: a chain declared as Grok, then Composer, then Sol went Grok, Composer, Luna, because Luna is what Composer's own chain names. One request now consumes one chain.
- Grok turns no longer report having read nothing. xAI reports the prompt size only when a response completes, so the Anthropic-shaped `message_start` cannot carry it, and `message_delta` was sending output tokens alone while the count the translator already had was discarded. The delta now carries it, so session totals stop under-reporting every Grok request.
- A raced startup marker no longer fails a launch. The router daemon publishes it through a rename, and Windows can refuse a read for the instant that rename is in flight; the waiting parent treated that as fatal and died with a bare "Permission denied" naming a file that was about to be readable. A refused read, a half-written file, and a payload that is not an object all now read as "not yet" and the caller polls again.

- Compaction no longer dies with `Model is not enabled for this session`. Claude Code runs compaction, and other background steps, by asking for a Haiku model by its exact ID rather than through the family slot Airlock seats for it. A session whose access policy marks Haiku unavailable has no such route, so the router refused the request and both automatic and manual `/compact` failed with a bare 400 and no way to tell why. Those requests are now served by the same background seat Claude Code was already told to use, and the substitution is recorded. Only the Haiku family is substituted, so a session can never quietly answer as some other model nobody enabled.
- A session no longer dies with the router. Claude Code reads the router address once, at startup, so a router that stopped took every later request with it and the client reported only `Connection refused - a firewall or proxy may be blocking it`, which names the wrong cause and offers no way back. The router is an ordinary python process holding an ephemeral port, so anything that sweeps processes by image name takes it down: seen live when a session ran `taskkill /F /IM python.exe` to restart a local model server and killed its own router. The launcher now watches the router process for as long as Claude Code runs and puts a replacement on the same address, up to five times, after which the session fails once rather than looping. The replacement starts with an empty record, so `airlock status` and the end of session summary say the router restarted and that earlier actions are not recorded. Liveness is read from the process, not from the port: a host that drops packets to a closed port rather than refusing them makes a dead router look like a slow one.
- The Haiku seat now reaches the router on Windows. The router substitutes the seated background model for the exact Haiku IDs Claude Code uses for compaction and other background work, but it learned that seat only from its own environment, and the Windows launcher keeps the session's model variables in the child environment it builds for Claude Code rather than in its own. The seat was therefore always empty there and the substitution never ran, so Windows sessions kept failing compaction with `Model is not enabled for this session` after the fix that was supposed to end it. The launcher now passes the seat explicitly.
- A dropped upstream body no longer reaches Claude Code as an unreadable one. The router relays upstream response headers as they arrive, so a reply that ended early still carried `Content-Encoding: gzip`, and the client reported `ZlibError fetching http://127.0.0.1:PORT/v1/messages` instead of the dropped connection it actually was. Seen live on a subagent whose upstream reset mid answer. The router now asks every upstream for an uncompressed body, which it already did for OpenRouter, so a short read stays readable and is reported and retried as the transport failure it is. This gives up response compression between Airlock and the provider, which costs nothing on the loopback proxy and costs some bandwidth on the direct Anthropic hop, in exchange for a dropped answer that can be recognised instead of one that cannot.
- A request for a model the session does not route is now recorded before it is refused. It previously left no trace at all, so the only evidence was a 400 at the client and the offending model ID was unknowable. `airlock status` and the end of session summary now name it.

- Failover peers are no longer treated as unknown-sized. Chains name a peer by the ID that reaches the provider, but context windows were filed only under the `[1m]` form of the same model, so every 1M Claude model looked size-unknown to the overflow pre-screen and was handed conversations that could not fit. Windows are now registered under both forms, matching what chain building already did. A declared OpenRouter route still has no window unless its `models.json` entry gives one, which stays deliberate: Airlock does not infer sizes it cannot verify.
- A rate-limited request now tells the client when to try again. Airlock replaces an upstream 429 with its own fixed message, and that reply carried no timing at all: the `Retry-After` value was read from the upstream, used to size the internal cooldown, and then dropped. Claude Code therefore saw a bare 429 with nothing marking it as a usage limit, reported it as a temporary server-side limit, and had no reset time to wait for. The reply now carries a `Retry-After` header rebuilt from the parsed number, or from the time left on the local cooldown when no upstream was contacted, and the same value is recorded in diagnostics and shown by `airlock status`. The header is synthesized from a validated number rather than copied, so no upstream bytes are reflected.
- A rate-limited model with no failover peer no longer claims its whole category is exhausted. The metered route is alone in its category and so has no chain at all, but it received the same "every model in this request's category is rate limited" message as a genuinely exhausted chain. It now says that the model has no failover peer, which is the actual situation.

- Installing Airlock while a session is running no longer blocks that session's Agents with an unexplained message. The session snapshot is verified against a digest of its canonical form, so a release that adds a field to the snapshot makes every already-running session fail that check, and every Agent call was refused with only "the active session permission set is invalid" to go on. The guard now recognizes this case, because the file's raw bytes still match the digest the launcher recorded while the reserialized form does not, and says that Airlock was updated and the session needs restarting. An edited snapshot fails the raw comparison instead, so it keeps the original wording and cannot borrow the friendlier one. Both cases are still denied.

- The doctor script no longer misreports enabled Grok models. The proxy prints its catalog separated by commas, and the check split it on spaces alone, so every entry but the last kept a trailing comma, matched nothing in the enabled list, and was listed as available but not enabled. Both the shell and PowerShell versions now strip the separator before matching.
- `scripts/doctor.sh` now checks that a Python candidate actually runs before it uses it, the same way the launcher already did. On Windows Git Bash the name `python3` usually resolves to the Microsoft Store placeholder, which sits on `PATH` but is not an interpreter, so the doctor picked it and reported that the OpenRouter registry and credential backend could not be determined on a healthy install. The doctor also tolerates the carriage returns a Python helper writes on Windows, which had left the first line of helper output unmatched.

- A spent provider balance now hands off instead of ending the request. xAI answers HTTP 402 when a Grok subscription's usage balance runs out, and OpenRouter answers it when account credits run out. That status reached the client untouched, so a declared chain never engaged even though another enabled model could have served the request. The router now walks the chain on 402 exactly as it does for a rate limit. The cooldown it shares with rate limits is short, so a balance that stays empty is retried periodically rather than parked for the rest of the session.
- Grok and Cursor browser login works again on Windows. Stock `claude-code-proxy` builds opened the OAuth login page through unquoted `cmd start`, which cut the address at the first ampersand, so x.ai answered with `Missing or invalid client_id`. The Windows installer now downloads Airlock's carried build (`0.1.35-airlock.1`) when no proxy is installed, verifies its SHA-256 checksum, and offers `-UpgradeProxy` to replace an existing stock build while keeping a backup. The carried source is published for review; macOS and Linux keep installing upstream through Homebrew because those platforms were never affected.
- An OpenRouter-bound request carrying Anthropic server-side tools no longer fails with an opaque upstream error. The router strips those declarations and their matching history blocks, records a diagnostic event, and keeps the payload valid. Set `AIRLOCK_OPENROUTER_KEEP_SERVER_TOOLS=1` to restore pass-through. Non-Anthropic roots should use the managed `airlock-web-tools` MCP server for public web access.
- Deterministic OpenRouter response problems return a non-retryable 400, so Claude Code does not resend the same full conversation repeatedly. A model-identity mismatch retains only the bounded printable identity needed for diagnosis. Retryable connection and availability failures remain 502 responses with bounded reasons.
- Selecting `/effort max` on an OpenRouter root no longer fails with a generic provider error. Claude Code emits an Anthropic-specific `max` level for an unknown custom model once Airlock enables its effort control, and pinned endpoints accept only the ordinary levels. The router now forwards that one value as `high`, keeps every other request field unchanged, and records a bounded diagnostic event.
- The Grok flagship route is `grok-4.6` again, now that proxy catalogs carry it. Beta.7 pinned that ID against `claude-code-proxy` builds that did not serve it, so a rate-limited Opus failed over onto it and the proxy answered `Unknown model "grok-4.6"` as a 400 on the conversation. The fix at the time was to drop back to `grok-4.5`. Proxy 0.1.35 lists `grok-4.5`, `grok-4.6`, and `grok-composer-2.5-fast`, so the pin moves forward and `grok-4.5` stays accepted as an alias of the one shipped flagship. A `grok-4.6` root declares its documented 500000-token window and compacts at 400000, leaving room for the summary request that compaction itself has to send. OpenAI roots, Composer, and a user-exported window are unchanged, and any inherited `CLAUDE_CODE_MAX_CONTEXT_TOKENS` is still dropped on every other root. The test that guards this now checks each Grok hop against the catalog rather than against one hard-coded ID, so the next pin move fails loudly if the proxy has not caught up.

## 0.1.0-beta.7 - 2026-08-23

### Added

- A local `airlock-web-tools` MCP server for sessions whose root cannot use Claude Code's own web tools. Built-in WebSearch executes on Anthropic's API, so a GPT, Grok, or OpenRouter root has no working search, and a pure profile cannot run WebFetch either because no Claude model sits in its Haiku slot. The managed plugin now ships a standard-library-only Python server exposing two tools: `web_search`, which queries DuckDuckGo's HTML endpoint and returns ranked links with short descriptions, and `fetch_page`, which reads one public page into context as plain text without a background model. Non-Anthropic roots get the server registered through managed session settings, get managed guidance steering them to these tools, and get the broken built-ins denied through managed permissions, so each session has exactly one working web path: a pure root loses both built-ins, while a hybrid root keeps the WebFetch that beta.7 fixed and loses only WebSearch. An Anthropic-rooted session receives none of this and stays exactly as Claude Code shipped it. Both tools make their own outbound requests to the public web, refuse private and loopback network addresses, revalidate every redirect hop, cap responses at 2 MB and 20 seconds, and truncate long pages. DuckDuckGo's HTML endpoint is an unofficial interface, so result format, availability, and rate limits can change without notice. Set `AIRLOCK_WEB_TOOLS=off` before launching to omit the server entry, its guidance, and the denials for that session. Because Claude Code does not start `mcpServers` entries carried in `--settings`, the launcher also hands the same single-server definition to Claude Code through an `--mcp-config` file that is created at launch and deleted when the session ends; without it the tools never appear in live sessions.

### Fixed

- A rich managed worker catalog could push the Windows launch command past the operating system's process limit, so `hybrid sonnet` and similar launches died with `Argument list too long` before Claude Code started. The launcher now stages the managed settings JSON, the composed routing guidance, and the web tools MCP config as digest-verified session files under the Airlock runtime directory and passes them with `--settings <file>`, `--append-system-prompt-file <file>`, and `--mcp-config <file>`, deleting each file when the session ends. Only the Agent catalog still travels inline because Claude Code ignores a file path there. The Python wrapper launcher already staged these files, so both entry points now behave the same way.
- WebFetch and session titles now work in a hybrid session. Claude Code spends its Haiku family slot on its own background work, including the step where WebFetch reads the fetched page, and refuses a model ID it does not recognize before any request leaves the machine. Airlock seated the economical discovery model there, so a GPT or Grok ID silently broke both features. A hybrid profile now seats a Claude model in that slot, preferring Claude Haiku and falling back to the other enabled Claude routes. Discovery keeps its own `AIRLOCK_DISCOVERY_MODEL` channel, and named `airlock-*` Agents are unchanged. A pure OpenAI, Grok, or OpenRouter profile has no recognized model to offer, so WebFetch cannot work there.
- The setup default for `AIRLOCK_ANTHROPIC_MODELS` now includes `haiku`, so the Haiku slot gets the cheapest Claude seat instead of falling back to a larger route. The example configuration that seeds a fresh Windows install now matches the setup default, so both platforms seat Haiku out of the box.
- `model=haiku` on a built-in Agent now resolves to the Haiku slot in a hybrid session, so the guidance and the Agent guard name the model the caller actually receives.
- The session router no longer reports every upstream failure as a retryable `502`. A timeout or a dropped connection still is one. A refused credential, a redirect, or a malformed upstream response is reported as non-retryable and names its own reason, so Claude Code stops resending the whole conversation ten times against a failure that cannot succeed.

### Changed

- The Grok flagship route now uses `grok-4.6`. `airlock grok`, hybrid root `grok`, and worker `airlock-grok` all pin that ID. The previous `grok-4.5` ID remains accepted as an alias of the same route.
- A `grok-4.6` root now declares its documented 500000-token window and compacts at 400000, so automatic compaction still has room for the summary request. OpenAI roots, Composer, and a user-exported window are unchanged.

## 0.1.0-beta.6 - 2026-08-22

### Fixed

- `airlock opr` now starts on Windows. The PowerShell launcher seeds the session effort for every other root but not for an OpenRouter root, so the Fast handoff binding had no managed effort to validate and the launch stopped with `Fast transition requires one valid managed effort`. The OpenRouter root now seeds the same effort as the other roots.

### Added

- A configurable Agent spawn depth, `airlock mode depth 1|2`, saved as `AIRLOCK_AGENT_DEPTH`. Depth stays 1 by default, which is the existing behaviour: named Agents disallow the Agent tool and every fan-out decision stays at the root. Depth 2 grants named Agents the Agent tool, and the managed guard then allows a worker to spawn only its own Agent type and rejects any model override on that call, so each worker's descendants run the model the root chose for it. The root still picks any model for any worker. The depth is enforced by Claude Code itself: Airlock sets `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` to the configured value, and the harness both caps the chain and decides whether a worker receives the Agent tool, so depth 2 cannot become depth 3.

## 0.1.0-beta.5 - 2026-08-22

### Added

- A fourth curated, opt-in OpenRouter preset for Ox Alpha, added with `airlock openrouter models add-preset ox-alpha`. It pins the exact model `stealth/ox-alpha`, its own canonical slug, and the single `stealth` endpoint, then runs the same confirmed public catalog verification as every other preset. OpenRouter currently prices the model at zero for prompt and completion tokens, but this is a stealth preview from an anonymous provider that retains prompts and completions, so the preset carries that retention, the temporary pricing, and the unverified benchmark claims in its community guidance. Setup and installation still do not enable any preset.

### Fixed

- A `ping` event arriving before `message_start` no longer fails an OpenRouter stream. The router scans the leading events of a response to confirm the model identity, and it treated any first event other than `message_start` as a protocol failure. Anthropic streams may legitimately send `ping` first, so a valid response could be rejected.
- An OpenRouter stream that begins with an upstream `error` event now reports that provider's own code and message instead of a generic complaint that the stream did not start with `message_start`. The provider text is bounded and stripped to printable ASCII.
- Stream identity failures now name the declared route, so a session with several OpenRouter routes shows which one failed. An unexpected first event also names what arrived.

## 0.1.0-beta.4 - 2026-08-15

### Added

- A session-local OpenAI Fast handoff. `airlock fast -r` starts one `gpt-5.6-sol-fast` root through the Codex proxy without changing saved `AIRLOCK_OPENAI_FAST`. Inside a managed Airlock session, `/airlock-fast` arms the current session; a clean exit lets its owning launcher resume the exact conversation once on fixed `gpt-5.6-sol-fast`. This is not Claude Code Anthropic `/fast`. Eligible OpenAI plan and proxy checks still apply, with no fallback. Hard kills, crashes, non-clean exits, hook failures, and expiry intentionally prevent relaunch. The private handoff marker is nonce-, PID-, cwd-, and session-bound and carries no credentials, prompts, transcripts, arbitrary executable data, or model choice. The installed managed plugin SessionEnd hook is required and is authorized as part of the Airlock plugin, not global hooks.

- An optional, opt-in OpenRouter path for hybrid sessions. Nothing about it turns on by itself: `airlock openrouter auth set-key` stores an OpenRouter API key using the operating system's own credential protection (the macOS Keychain, Windows DPAPI scoped to the current Windows user, or the Linux Secret Service through `secret-tool`), with no plaintext file fallback, and `airlock openrouter models add ROUTE MODEL ENDPOINT` declares one exact routable model that is not an alias and one exact serving endpoint in a small local registry after checking both catalog identities against OpenRouter's public catalog and confirming by name.
- `airlock openrouter auth status` and `airlock openrouter auth logout`, and `airlock openrouter models list`, `remove`, and `refresh`, for managing the stored key and the declared routes. `refresh` reports what changed against the public catalog and only saves it with `--apply`. The endpoint tag, catalog provider name, provider-registry routing slug, endpoint quantization, and separate canonical slug are frozen and must not drift during refresh. Concurrent registry updates fail with a rerun message instead of silently losing a change.
- Three curated, opt-in OpenRouter presets for Kimi K3, DeepSeek V4 Flash 0731, and Qwen 3.6 27B. `airlock openrouter models presets` lists them offline, and `airlock openrouter models add-preset NAME` expands one into an exact model, frozen canonical provenance, default route, and pinned endpoint before running the normal confirmed public catalog checks. Setup and installation do not enable any preset.
- Matching preset workers receive fixed, clearly labeled community-derived suggested-use guidance in their Agent descriptions. The guidance is unverified, is not a capability, price, or availability guarantee, and never enters registry JSON, session snapshots, route policy, or Agent prompts. Airlock does not accept custom prompt text or descriptions through these commands.
- A declared route appears as a named `airlock-or-ROUTE` Agent inside a hybrid session, never through OAuth. Every request constrains OpenRouter to the verified provider-registry slug and endpoint quantization with fallback routing turned off. Provider plus quantization must identify one listed endpoint, and a response is accepted only for the exact routable or frozen canonical model identity. Both the model and endpoint must report `tools` and `tool_choice` support. OpenRouter's `count_tokens` operation is not available on these routes.
- `airlock opr [ROUTE] [Claude arguments...]`, an exclusive OpenRouter-only root command. It starts a session whose root is exactly one declared registry route, named directly or picked from an offline interactive list of declared routes; outside an interactive terminal, or for an unknown, disabled, or misspelled route, it fails closed instead of guessing. `--model`/`-m` cannot be forwarded, because the root is selected by exact registry route rather than a typed model ID. An `opr` session has no dependency on Claude, Codex, or Grok credentials and does not start the OpenAI subscription proxy. It has no saved default: every launch names its route or asks, and it does not change guided setup or any saved profile.
- Because Airlock does not verify a declared model's real capability, context window, or cost, an OpenRouter Agent is normally treated as extra usage and needs the same `Extra usage authorized: yes` confirmation as any other extra-usage worker under the default `ask` policy. The one route explicitly selected as the `airlock opr` root is the exception: it carries that session's normal traffic and is not itself gated by the extra-usage policy, the same as any other explicit session root. Any other declared route that becomes available in that same `opr` session still follows the normal extra-usage policy.
- A declared route's verified metadata expires after 30 days. Run `airlock openrouter models refresh --apply` before it expires; an expired or otherwise invalid registry file stops every Airlock session, not only ones using OpenRouter, until it is refreshed or the affected route is removed.

### Changed

- OpenRouter catalog verification now accepts exact model entries whose `alias_target` field is omitted or explicitly null, matching current catalog responses, while still rejecting every declared non-null alias target and all dynamic model selectors.
- The exclusive OpenRouter-only root command was briefly documented as `airlock orp`. That spelling is rejected; use `airlock opr` instead.

### Fixed

- Windows sessions no longer place generated routing guidance and managed settings JSON directly on Claude Code's command line. They use private session files for those two values, keep exact Agent JSON inline because Claude Code has no Agent-file option, clean the files after exit, and reject any remaining command that exceeds the `CreateProcessW` limit before starting the router or Claude. This fixes `[WinError 206]` for `airlock hybrid sol -r` with the complete managed worker catalog and enabled OpenRouter routes.
- OpenRouter routes now preserve Claude Code's custom-model notice while moving its non-standard `messages[].role = "system"` entry into the Anthropic Messages API's top-level `system` field. Strict endpoints such as the pinned Qwen 3.6 27B Chutes route no longer reject the native Agent request with HTTP 400, while exact provider and quantization pinning, disabled fallback, tools, thinking, cache controls, metadata, and response-model validation remain unchanged.
- Windows hybrid resume now carries the same current validated policy through Agent rendering, exact permission generation, and managed session settings. `airlock hybrid sol -r` therefore accepts only currently declared OpenRouter workers instead of rejecting them as unexpected, while stale, invalid, or undeclared routes still fail closed.
- The curated Kimi K3 preset now pins the uniquely identifiable DigitalOcean endpoint instead of Morph, whose current catalog entries can no longer be distinguished by provider and quantization alone.
- OpenRouter endpoint tags such as `deepinfra/fp4` are no longer sent as provider names. Airlock now resolves the catalog provider name through OpenRouter's provider registry, routes with its exact slug plus endpoint quantization, rejects ambiguous mappings, and accepts only the exact routable or frozen canonical response identity.
- OpenRouter requests no longer require an endpoint to advertise every optional field in Claude Code's native Messages payload. Exact provider and quantization constraints, disabled fallback, required `tools` and `tool_choice` catalog support, and exact response-model validation remain enforced.
- `airlock session-usage` now omits OpenRouter summary groups instead of rejecting the whole report after an OpenRouter Agent runs. Anthropic, OpenAI, and Grok totals remain available, and the text view states that OpenRouter belongs to a separate account.
- Curated community guidance now appears only when a declared route matches the preset's exact model, pinned endpoint, and frozen canonical provenance. A manual route that reuses only the model ID no longer inherits guidance researched for another endpoint or model snapshot.
- Windows now streams OpenRouter helper output directly and preserves each helper's exact exit status, so confirmation questions are visible before the helper waits for an answer instead of appearing to hang.
- A hybrid session that cannot start its native router now reports the router's own reason instead of a single generic line. A session with declared OpenRouter routes and no stored key, for example, now says the OpenRouter credential is missing.
- Windows sessions run by an elevated administrator now clean up their policy snapshot. Windows gives files created by an administrator to the built-in Administrators group rather than to the account itself, which failed Airlock's owner check and left the snapshot in the session runtime directory after exit. The session snapshot and the Fast handoff marker now carry an explicit private owner and access list, matching how saved Airlock state is already written.
- The POSIX launcher now preserves its original standard input explicitly when keeping Claude as a background child, and treats deliberately closed input as end-of-file, rather than depending on incidental Bash redirection state for the interactive TUI.

## 0.1.0-beta.2 - 2026-08-09

### Added

- Grok subscription path (Phase 1 of multi-provider work): `airlock grok`, hybrid roots `grok` / `composer`, workers `airlock-grok` and `airlock-composer`, router provider label `grok` (shared loopback proxy with Codex), and `airlock proxy grok auth` for Grok OAuth. - `airlock session-usage` reports cumulative provider-reported request and token totals from the active hybrid router without rewriting responses or inventing missing counts.
- An opt-in Sol long-context helper sends one synthetic root-only request through standard input and fails unless provider-reported input plus cache usage exceeds 300,000 tokens and both distant markers return.

### Changed

- Grok routes are opt-in. A hybrid session gains Grok workers only when the saved configuration enables them or the root is itself a Grok model. Earlier work in this cycle enabled Grok for every hybrid session, which advertised workers to accounts without a Grok login.
- Hybrid provider-boundary guidance now names only the providers a session actually enabled, instead of always describing all three.
- A session that confirms the proxy is signed out of Grok disables the Grok routes rather than offering workers whose first request would fail. An unknown login state leaves the configured routes alone.
- Every canonical OpenAI/GPT model ID is now bare. Legacy GPT IDs ending in `[1m]` remain accepted at launcher, setup, and saved-config input boundaries and normalize immediately; native Claude Opus 5, Sonnet 5, and Fable 5 retain `[1m]`.
- Session guidance now names only the providers and workers a session actually enabled. A Grok-only session previously spent most of its guidance describing Luna armies and Anthropic workers it could not call.
- Routine Explore now uses the schema-valid `haiku` family slot instead of silently inheriting a different premium root. Airlock resolves all four built-in Agent family slots to exact models enabled for the active session, and named `airlock-*` Agents remain the exact-model interface.
- Native Anthropic roots now leave Claude Code's process-wide auto-compact override unset. The authorized Sol proof above 300,000 tokens did not pass, so Sol now uses the honest bare ID `gpt-5.6-sol` and OpenAI/Grok roots retain the saved conservative fallback. An explicitly exported `CLAUDE_CODE_AUTO_COMPACT_WINDOW` or `AIRLOCK_CONTEXT_WINDOW` still wins for the whole process.
- Grok and Composer now have explicit routing rules rather than only a descriptive role-map entry, so the orchestrator can positively select them. Composer is described as the agentic coding worker it is instead of a summarizer, and is eligible for automatic fan-out.

### Fixed

- Claude Code's Agent input accepts only the `fable`, `opus`, `sonnet`, and `haiku` family values, while Airlock previously told built-in Explore to retry with an exact GPT ID that the tool schema rejected. Every pure and hybrid profile now owns all four family slots, validates each exact target against the active policy, reserves Haiku for economical discovery, and labels each slot with the model it will call.
- The setup PTY tests now include the Grok subscription question in the recommended hybrid path, so Linux and macOS CI reaches and applies the final review instead of running out of keystrokes.
- Git Bash on Windows no longer lets the hybrid router lose its owner when the launcher starts Claude. The launcher stays alive, forwards terminal signals, returns Claude's exact status, and shuts the router down after Claude exits.
- Grok-only sessions inherited the global OpenAI utility model as `ANTHROPIC_SMALL_FAST_MODEL`, so Claude Code could silently send background work to GPT from a profile that promised to stay on Grok. The utility slot is now Composer or the enabled Grok fallback.
- The Windows `airlock models` help omitted the Grok-only command and both Grok root aliases even though the launch paths were installed and working.
- Claude Opus 5, Sonnet 5, and Fable 5 ran at 200000 tokens instead of their native 1000000. Claude Code grants those models their full window only while `ANTHROPIC_BASE_URL` is unset or points at `api.anthropic.com`, and Airlock always points it at the session router, so every Claude root and Claude worker silently lost four fifths of its context and compacted far more often than the same model outside Airlock. All three are now requested as `claude-opus-5[1m]`, `claude-sonnet-5[1m]`, and `claude-fable-5[1m]`, which Claude Code honours from behind the router. Claude Haiku 4.5 is genuinely a 200000 token model and is unchanged.
- The router allow-list derived a suffix-free wire ID for OpenAI models only, which was correct only while OpenAI was the only provider whose IDs carried `[1m]`. It now applies to every provider, so an Anthropic worker no longer fails closed against its own route.
- `require_proxy_environment` hardcoded a `gpt-` root prefix, so the Windows launch path rejected every Grok-only session.
- The Windows launcher had no `grok` command, no Grok hybrid roots, and never passed the Grok agent catalogs to the access helper.
- `airlock.ps1` resolved every managed path from `$HOME\.config\airlock` while `install.ps1` honoured `AIRLOCK_CONFIG_DIR`, so a Windows install into a custom directory validated another installation's files.
- The installers refused to update any agent catalog whose contents changed, because catalogs carried no managed marker. They now carry one, and a file whose hash matches the installed bundle's record for that component is recognised as Airlock's own. A file with neither is still refused.
- `setup.sh` defaulted `AIRLOCK_HYBRID_MODEL` to `sol` while both launchers fall back to `sonnet`, so rewriting a config that never had the key silently moved the hybrid root. A new setup still recommends Sol.
- Earlier context handling applied the saved 272000 fallback to every root, including native Anthropic roots that Claude Code could size itself. Native Anthropic roots now stay model-aware. OpenAI and Grok roots keep the fallback because the guarded Sol request above 300,000 tokens exited with status 1 and did not produce a valid proof.
- `AIRLOCK_CONTEXT_WINDOW` accepted values Claude Code discards. Claude Code takes 100000 to 1000000 and ignores anything else without a word, so an out-of-range number looked applied while doing nothing. Both launchers now reject it before the session starts. The Windows launcher previously checked only that the value was a positive integer, and the POSIX launcher did not check at all.
- Router diagnostics never reported token usage for Anthropic routes. Anthropic answers with `Content-Encoding: gzip`, and the observer read the compressed bytes, so it could never find a usage object. It now decodes a private copy of the response to read the counts. The bytes forwarded to the client are still passed through untouched, and a response in an encoding the standard library cannot read records no usage instead of guessing.
